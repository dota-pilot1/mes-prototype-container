# 메뉴 관리 개선 방법

> **요약**: beauty-book의 메뉴 시스템은 이미 DB-driven으로 잘 설계되어 있다. 구조를 갈아엎을 필요는 없고, **`legacyCode` 필드 하나만 backport**하면 보일러플레이트가 한 단계 더 단단해진다. 급하지 않으니 이 문서를 근거로 나중에 적용해도 된다.

작성일: 2026-05-30
대상: `beauty-book-server` / `beauty-book--front`

---

## 1. 현재 상태 — 이미 잘 되어 있음

beauty-book의 헤더 메뉴는 **DB-driven**이다. 서버 부팅 시 `MenuSeeder`가 메뉴 테이블을 upsert하고, 프론트 헤더는 메뉴 API로 평면 목록을 받아 `parentId` 기준으로 트리를 만들어 렌더한다.

```
MenuSeeder.java → menus 테이블(DB) → GET /api/menus → Header.tsx · buildTree() → 헤더 렌더
```

### 좋은 점 (그대로 유지)

- **시더 한 파일만 고치면 됨** — `buildTree()`가 `parentId`로 트리를 자동 구성하고 `path`로 이동하므로, 메뉴를 추가/재구성할 때 **프론트 수정이 필요 없다.**
  - (비교) towercrane은 메뉴 추가 시 3개 파일(DB 시드 + 헤더 라우트맵 + 라우터)을 동시에 수정해야 함.
- 자식이 있는 항목은 자동으로 드롭다운(`DropdownMenu`) / 관리자 메가메뉴(`AdminMegaMenu`)로 렌더.
- `requiredRole`로 역할별 노출 제어.

### 관련 파일

| 파일 | 역할 |
|---|---|
| `beauty-book-server/.../config/MenuSeeder.java` | 메뉴 정의 + DB upsert |
| `beauty-book--front/src/widgets/header/ui/Header.tsx` | `buildTree()` + 드롭다운/메가메뉴 렌더 |
| `beauty-book--front/src/entities/menu/api/menuApi.ts` | `GET /api/menus` |

## 2. 개선 포인트 — `legacyCode` backport (유일한 실질 차이)

파생 프로젝트인 **hospital-book**에는 `MenuDef`에 `legacyCode` 필드가 추가되어 있는데, beauty-book에는 아직 없다. 이 한 가지가 유일한 차이이자 개선할 가치가 있는 부분이다.

### 왜 필요한가

메뉴의 `code`는 부모 지정·upsert의 키다. 운영 중에 `code`를 바꿔야 할 때(예: 의미가 바뀌어 리네이밍), **그냥 바꾸면 시더가 "새 메뉴"로 인식**해서 기존 행과 중복 생성되거나 데이터가 꼬인다.

`legacyCode`가 있으면 "예전 code로 저장된 기존 행을 찾아 새 code로 갱신(rename)"이 가능해 **데이터 유실 없이 안전하게 리네이밍**할 수 있다.

> 실제 사례(hospital-book): `TELEMEDICINE` → `RESERVATION_CONSULTATIONS` 로 code를 바꾸면서 기존 메뉴 행을 그대로 승계했다.

### 적용 방법 (3단계)

#### (1) `MenuDef` 레코드에 `legacyCode` 추가

```java
// Before
private record MenuDef(
        String code, String parentCode, String label, String labelKey,
        String path, String icon, String requiredRole, int displayOrder
) {}

// After — code 다음에 legacyCode 추가
private record MenuDef(
        String code, String legacyCode, String parentCode, String label, String labelKey,
        String path, String icon, String requiredRole, int displayOrder
) {}
```

#### (2) upsert 조회 로직에 fallback 추가

```java
Optional<Menu> existing = menuRepository.findByCode(def.code());
if (existing.isEmpty() && def.legacyCode() != null) {
    existing = menuRepository.findByCode(def.legacyCode());
}

if (existing.isPresent()) {
    Menu menu = existing.get();
    menu.renameCode(def.code());   // 기존 행의 code 를 새 code 로 갱신
    menu.update(/* ... */);
    continue;
}
```

> `Menu` 엔티티에 `renameCode(String)` 메서드가 없으면 함께 추가한다(hospital-book 참고).

#### (3) 기존 `defs` 줄에 `legacyCode` 인자 채우기

리네이밍이 필요 없는 기존 메뉴는 전부 `null`로 둔다.

```java
new MenuDef("DASHBOARD", null, null, "대시보드", "nav.dashboard", "/dashboard", "LayoutDashboard", null, 0),
//                       ^^^^ legacyCode = null
```

## 3. 메뉴 추가/재구성 치트시트 (현행 방식)

### 루트 메뉴 한 개 추가

```java
// code           legacy parent label       labelKey       path        icon         role  order
new MenuDef("NOTICE", null, null, "공지사항", "nav.notice", "/notices", "Megaphone", null, 5),
```

### 그룹(드롭다운) 만들기 — 부모(path=null) + 자식들(parentCode 지정)

```java
// 부모 — 자식보다 반드시 위에 둘 것 (시더가 부모를 code로 조회하므로)
new MenuDef("MYPAGE", null, null,     "마이페이지", "nav.mypage", null,    "UserCircle", null, 3),
new MenuDef("MY_X",   null, "MYPAGE", "내 X",       "nav.myX",    "/my-x", "Calendar",   null, 0),
new MenuDef("MY_Y",   null, "MYPAGE", "내 Y",       "nav.myY",    "/my-y", "BarChart3",  null, 1),
```

### 개발용/내부 메뉴 분리

삭제 대신 `requiredRole = RoleSeeder.ROLE_ADMIN` → 일반 사용자 헤더에서 사라지고 관리자만 노출.

### 적용 절차

1. `MenuSeeder.java` `defs` 수정 (부모 먼저, `code` 중복 없음)
2. 새 `path`면 프론트에 해당 페이지 라우트 존재 확인
3. **서버 재시작** → DB upsert 실행
4. 브라우저 새로고침 (헤더 메뉴는 `staleTime 5분` 캐시)

## 4. 결론 / 우선순위

| 항목 | 필요성 | 시점 |
|---|---|---|
| 메뉴 메커니즘 리팩터링 | ❌ 불필요 (이미 동일 구조) | — |
| `legacyCode` backport | ⭐ 권장 (보일러플레이트 강화) | 여유 있을 때 |
| 디자인 토큰(브랜드 색) 문서화 | 선택 | 차후 |

**지금 당장 코드를 고칠 필요는 없다.** 이 문서를 근거로, code 리네이밍이 실제로 필요해지는 시점이나 보일러플레이트를 정비하는 김에 `legacyCode`를 backport하면 된다.
